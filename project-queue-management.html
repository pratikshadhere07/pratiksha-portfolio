Smart Queue Management System

A real-time digital queuing and smart token dispatch platform built with Java and Spring Boot to eliminate physical waiting lines, minimize crowd congestion, and optimize customer service throughput.

The Crowding Dilemma

High-density service facilities like hospital emergency desks, banking branches, and public utility offices suffer chronic delays due to unstructured, physical lineups. Customers have no transparency into their estimated wait time, while counter operators cannot predict incoming footfall surges.

Traditional token displays often lack real-time synchronization, resulting in missed turns, skipped tokens, and counter miscommunications.

Real-Time WebSocket Architecture

The system utilizes a Spring Boot backend integrated with STOMP WebSockets over SockJS. When an operator hits "Next Customer", a lightweight event payload is broadcast instantly to all connected waiting-room monitors with sub-50ms latency.

The architecture supports distinct priority categories (Elderly, Emergency, Normal), recalculates dynamic estimated wait times using rolling service averages, and outputs chime frequencies to alert waiting patrons.

Core Features

  • Multi-Screen Live WebSocket Sync: Real-time token updates across unlimited monitors with zero manual polling.
  • Dynamic Wait-Time Prediction: Mathematical estimation based on current queue depth and counter historical velocity.
  • Operator Control Center: Dedicated counter workflow allowing transfers, pauses, recalls, and emergency overrides.
  • Analytics & SLA Tracking: Measures peak-load bottlenecks, average wait durations, and counter efficiency.
